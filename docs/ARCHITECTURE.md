# 架构说明

## 数据流

```text
%USERPROFILE%\.codex
        │ 只读扫描
        ▼
CodexMonitor（主进程）
        │ 聚合项目、任务、额度与历史
        ▼
Electron IPC / preload 安全桥
        │ 快照修订号去重
        ▼
Renderer（桌宠、指标卡与 SVG 图表）
```

## Electron 主进程

`electron/main.cjs` 创建无边框透明窗口，负责：

- 精简版和详细版窗口尺寸动画。
- 每 2 秒检查一次监控快照。
- 只在快照修订号变化时发送 IPC。
- 最小化、关闭和模式切换等窗口级操作。

渲染进程保持 `contextIsolation: true`、`nodeIntegration: false` 和 `sandbox: true`。`preload.cjs` 只暴露最小化的消息接口。

## 日志监控器

`electron/codex-monitor-v2.cjs` 从本机 Codex 目录读取：

- 当前选中项目与会话—项目分配关系。
- 任务开始、计划更新、完成和中止事件。
- 累计 Token、最近轮次 Token、rate-limit windows、模型与推理强度。

活跃日志采用增量尾部读取；未变化时复用短期快照。每个会话和项目保持累计高水位，以抵御日志尾部轮换或短暂缺失导致的显示倒退。

## 指标边界

- 账户窗口来自最新可用 rate-limit 事件，不归属于单个项目。
- 项目累计来自所有匹配项目根路径或显式项目分配的主会话与子会话。
- 当前任务来自当前项目最近的用户会话。
- 计划百分比仅在日志中存在 `update_plan` 时计算。

## 渲染层

`src/renderer-v2.js` 根据快照更新两种界面模式：

- 精简模式：人物、任务进度和窗口余额。
- 详细模式：额度环、任务、项目统计、两层消耗图表与运行信息。

SVG 图表按数据签名重绘，柱体交互使用统一事件委托。纵轴根据 SVG 实际缩放比例抵消水平滚动，保持刻度固定。

## 隐私设计

应用不需要远端后端。业务数据只从本机日志读入内存并渲染到本机窗口；不会写回 Codex 文件，也不会主动上传项目内容。
