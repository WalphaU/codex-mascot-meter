# 架构说明

## 数据流

```text
%USERPROFILE%\.codex
        │ 只读扫描
        ▼
CodexMonitor（主进程）
        │ 聚合项目、任务、额度与历史
        ▼
Electron IPC / preload 安全桥
        │ 快照修订号去重
        ▼
Renderer（桌宠、指标卡与 SVG 图表）
```

## Electron 主进程

`electron/main.cjs` 创建无边框透明窗口，负责：

- 精简、详细和动态桌宠三种模式的窗口尺寸动画，以及面板展开时的位置校正。
- 使用 Windows 原生 DIP 光标坐标拖动桌宠；松手、失焦或取消捕获时结束拖拽。
- 每 2 秒检查一次监控快照。
- 只在快照修订号变化时发送 IPC。
- 最小化、关闭和模式切换等窗口级操作。

渲染进程保持 `contextIsolation: true`、`nodeIntegration: false` 和 `sandbox: true`。`preload.cjs` 只暴露最小化的消息接口。

## 日志监控器

`electron/codex-monitor-v2.cjs` 从本机 Codex 目录读取：

- 当前选中项目与会话—项目分配关系。
- 任务开始、计划更新、完成和中止事件。
- 累计 Token、最近轮次 Token、5 小时和周 rate-limit windows、模型与推理强度。
- 从任务上下文和 thread_settings_applied 读取设置，新会话缺少设置时沿用项目最近的有效值。

活跃日志采用增量尾部读取；未变化时复用短期快照。每个会话和项目保持累计高水位，以抵御日志尾部轮换或短暂缺失导致的显示倒退。

## 指标边界

- 账户窗口来自最新可用 rate-limit 事件，不归属于单个项目。
- 项目累计来自所有匹配项目根路径或显式项目分配的主会话与子会话。
- 当前任务来自当前项目最近的用户会话。
- 计划百分比仅在日志中存在 `update_plan` 时计算。

## 渲染层

`src/renderer-v2.js` 根据快照更新三种界面模式：

- 精简模式（300×380 DIP）：人物、任务进度、5 小时和周额度。
- 详细模式（432×680 DIP）：双窗口额度卡片、任务、项目统计、两层消耗图表与运行信息。
- 动态模式（270×320 DIP）：连续待机、点击回应、拖拽挣扎和落地反馈。

`PetAnimationController` 统一管理动作优先级、中断和清理。`PetIdlePlayer` 使用本地图集与 Canvas 2D 补间，`PetSequenceAdapter` 保留 8 帧序列接口。隐藏、退出动态模式或减少动态效果时停止待机绘制，加载或绘制失败时回退静态人物；不调度周期随机动作。

SVG 图表按数据签名重绘，柱体交互使用统一事件委托。纵轴根据 SVG 实际缩放比例抵消水平滚动，保持刻度固定。

## 隐私设计

应用不需要远端后端。业务数据只从本机日志读入内存并渲染到本机窗口；不会写回 Codex 文件，也不会主动上传项目内容。
